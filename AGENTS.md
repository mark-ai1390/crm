## Начало сессии
1. Прочитайте AGENTS.md, claude-progress.md и feature_list.json. Проверьте git status/log; сохраните чужие изменения.
2. Для работ с Figma прочитайте state.json и соответствующие навыки. Продолжайте по сохранённым ID, не дублируйте страницы.
3. Запустите ./init.sh. При падении исправьте причину до новых функций.
4. Сохраняйте работающие операции. Старый интерфейс доступен в public/legacy/index.html, модели и проверки legacy остаются.

## Стек и реальные команды
- Статические HTML/CSS/JavaScript ES modules, Node.js >=22, без внешних runtime-зависимостей.
- public/assets/v2/: model.js — транзакции и инварианты, seed.js — данные, ui.js — компоненты, views.js — экраны, forms.js — формы, app.js — события и навигация, styles.css — токены и адаптация.
- `npm run check` — синтаксис JS, Figma-сниппетов, схема задач и локальные ресурсы.
- `npm test` — legacy-регрессии, бизнес-сценарии v2, импорт/миграция, рендер маршрутов, семантика и контраст. Это не браузерная приёмка.
- `npm run build` — воспроизводимая сборка public/ → dist/.
- `npm run dev` — public/ на 5173; `npm run preview` — dist/.
- `./init.sh` — check, test, build. Запуск сервера отдельно через RUN_START_COMMAND=1 разрешён только в поддерживаемой среде.
- В managed Sites без control-browser не запускайте preview и не устанавливайте другой браузер. Зафиксируйте ограничение и продолжайте доступные проверки.
- .openai/hosting.json сохраняет ID существующей CRM. Источники и публикация Sites — только через поддерживаемый source helper.

## Продуктовые инварианты
- Деньги хранятся в целых копейках. Цена/SKU/название строки и контакты доставки — снимки; редактирование каталога не меняет прошлые заказы.
- Доступно = наличие − резерв подтверждённых неотгруженных заказов. Дубликаты SKU агрегируются при проверке наличия.
- Отгрузка списывает наличие и снимает резерв, отмена освобождает резерв. Возврат товара и возврат оплаты — отдельные операции.
- Команды атомарны. При ошибке валидации или записи storage исходное состояние сохраняется.
- Заказ, клиент, товар, менеджер, задача, сообщение и аналитика используют единый store v2. Ключ v1 не удаляется автоматически.
- Импорт проверяет формат, уникальность и связи. Не затирать повреждённое сохранение без явного действия пользователя.
- Новая запись запускает включённое правило создания задачи локально. Пробный запуск не создаёт задачи, повторный рабочий запуск идемпотентен.
- Сообщения/платежи/доставка — локальная демонстрация. Не имитировать реальные отправки, банковские операции или production-авторизацию. Демо-дата фиксирована: 12 октября 2026.

## Визуальные правила
- Inter, фирменный SVG 4sales, navy-сайдбар, светлые поверхности, спокойный синий акцент.
- Sidebar 228/88 px, профиль внизу с отступом 20 px, средняя область прокручивается. Вложенность заменена контекстными вкладками.
- Семантические CSS-переменные соответствуют Figma. Текстовые пары контраста >=4.5:1. Минимум анимации, reduced motion обязателен.
- Общие table/field/button/card/badge/modal используются во всех разделах. Не добавлять декоративные эффекты без продуктовой причины.
- Все динамические пользовательские строки экранировать. Никаких временных Figma URL в рабочем сайте.
- В публичный GitHub не переносить личные фото; для аватаров использовать инициалы. Не коммитить credentials или пользовательские сохранения.
