# 4sales CRM — правила работы

Это новая демонстрационная CRM Марка Сангинова для портфолио, а не сайт с чат-примером. Канонический репозиторий: https://github.com/mark-ai1390/crm, ветка main. Старый 4sales-about — только справочный источник; не изменяйте его.

## Источники и начальная точка
- Прочитайте crm-implementation-plan.md. Он подготовлен до реализации, относится также к старому прототипу; текущий статус фиксируется в claude-progress.md.
- Макеты: https://www.figma.com/design/ufCGdzahHmwbLQWYjeAzNp/CRMED?node-id=1125-17038.
- Главная страница: новый дашборд 1478:35960. Старый 954:31558 не является целью.
- На начало настройки 2026-10-04 код нового сайта отсутствовал; макеты и план были готовы. Это историческая точка, не утверждение о текущем состоянии.

## Старт каждой сессии
1. Проверьте pwd и прочитайте этот файл, claude-progress.md и feature_list.json.
2. Посмотрите git log --oneline -5 и git status --short. Сохраните чужие изменения.
3. Выберите одну незавершённую задачу с наивысшим приоритетом. Сначала исправьте падающую базовую проверку.
4. Запустите ./init.sh. Для сервера: RUN_START_COMMAND=1 ./init.sh или npm run dev.
5. Проверьте связанную с задачей функциональность; отдельно фиксируйте отсутствие браузерной проверки.

## Стек и команды
- HTML, CSS с семантическими переменными, JavaScript ES modules. Node.js >=22; сторонних зависимостей пока нет.
- public/ — сайт и локальные ресурсы; public/assets/js/ — данные и поведение; scripts/ — служебные команды.
- npm run check — синтаксис, целостность проекта и локальных ссылок.
- npm test — расчёты, CSV, состояние навигации и связи контролов в разметке. Эти проверки не заменяют DOM- и браузерную приёмку.
- npm run build — воспроизводимое копирование public/ в dist/.
- npm run dev — локальный сервер public/ на порту 5173; npm run preview — сервер dist/.
- .openai/hosting.json хранит идентификатор Site и static.directory=dist. Секреты, токены и пользовательские данные не коммитить.

## Дизайн и поведение
- Сохраняйте авторский визуальный язык Figma: Inter, логотип Rubik, тёмный сайдбар, светлый фон, синий акцент.
- Новый дашборд: сайдбар 228 px, компактный 88 px по референсу пользователя; при 1440 px сетка контента 740 + 24 + 400, отступы 24 px.
- Компоненты, иконки и фотографии берите из исходных материалов; используемые ресурсы сохраняйте локально. Не используйте временные адреса Figma.
- Продажи и вложенные Товары и склады раскрываются отдельно. Подсветка обозначает выбранную строку, а не весь вложенный блок.
- Средний чек, итоги и доли рассчитываются из данных; период и прогноз имеют явную подпись.
- Видимые действия работают либо открывают честное демонстрационное состояние. Не изображайте отправку сообщений, оплату или внешнюю AI-интеграцию.
- Первая очередь — новый дашборд. Заказы, клиенты, коммуникации, товары, менеджеры и новый заказ остаются отдельными задачами.
- Адаптацию для телефона проектируйте по плану и отмечайте как предлагаемую: готовых мобильных макетов нет.
- Анимации короткие и спокойные; reduced motion отключает декоративное движение. Не добавляйте сторонний UI ради эффекта.

## Готовность и завершение
- passing разрешён только после всех перечисленных для задачи проверок с записанными доказательствами.
- Реализованный код с незавершённой браузерной/визуальной проверкой отмечайте needs_verification, а ограничение — в notes и журнале.
- Не удаляйте критерии и не ослабляйте проверки ради зелёного статуса.
- Перед завершением обновите feature_list.json и claude-progress.md: что сделано, какие команды прошли, ограничения, следующий шаг.
- Коммитьте безопасные этапы отдельно: сначала настройка проекта, затем главная страница. Публикуйте только успешно собранное состояние.
