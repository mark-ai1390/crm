# 4sales CRM - архитектура и визуальное направление

## Продукт и предел демонстрации

Операционная CRM для небольшой команды интернет-магазина. Основной пользователь - менеджер продаж, дополнительные роли - руководитель и сотрудник склада. Демонстрация должна давать законченный путь от нового заказа до доставки и объяснять каждый показатель. Это локальный демонстрационный продукт, а не готовая многопользовательская система с платёжными провайдерами.

## Навигация

| Основной раздел | Страницы внутри |
|---|---|
| Обзор | рабочий день, очередь внимания, динамика и каналы |
| Заказы | все / мои / требуют внимания / к отправке; preview; карточка; создание/редактирование |
| Клиенты | список и сегменты; карточка 360; создание/редактирование |
| Сообщения | входящие / email / SMS / черновики; диалог; шаблоны |
| Каталог | товары; остатки/склады; движения; категории, бренды, контрагенты |
| Задачи | мои / все / просроченные; календарь |
| Аналитика | деньги, заказы, каналы, менеджеры; исходные записи |
| Команда | менеджеры, карточка нагрузки и назначение |
| Автоматизация | правила; редактор; пробный запуск; журнал |
| Настройки | пространство; статусы/доставка/оплата; роли; каналы; профиль; демо-данные |

Основные разделы находятся на одном уровне. Вложенные справочники - вкладки и локальная навигация. Global search ищет заказ, клиента, SKU и задачу. Профиль всегда внизу sidebar, фон совпадает с ним, нижний отступ 20 px. Sidebar 228 px, compact 88 px с одинаковыми слотами иконок. Мобильное меню - drawer, а не сжатая настольная навигация.

## Данные и инварианты

| Сущность | Связи и правила |
|---|---|
| Customer | managerId; уникальный email/телефон; заказы, сообщения, задачи |
| Order | customerId, managerId, channel, items, delivery snapshot; неизменный номер |
| OrderItem | productId, qty, unitPriceKopecks, name/sku snapshot; цена сохраняется |
| Payment | orderId, amountKopecks, paidAt, kind payment/refund; сумма не больше допустимого остатка |
| Product | уникальный SKU, цена/себестоимость, categoryId/brandId; записи stock по складам |
| Stock | productId, warehouseId, onHand; reserved вычисляется по подтверждённым неотгруженным заказам |
| Movement | приход/списание/отгрузка/возврат; товар, склад, количество, причина, время |
| Task | managerId, dueDate, priority, orderId/customerId, done; одна понятная следующая операция |
| Message | customerId, optional orderId, channel, direction, body, state; связность получателя проверяется |
| Event | entity/id, actor, time, kind, описание; история добавляется, не переписывается |
| Rule / Run | событие/условие/действие; enabled; журнал, ключ от повторного выполнения |

Деньги - целые копейки. Сумма = сумма(qty × зафиксированная цена) - скидка + доставка. Оплачено = платежи - возвраты. Долг = итог - оплачено. Нельзя сделать отрицательный долг, количество или доступный остаток. Текущая цена товара и профиль клиента не меняют исторические снимки заказа. Изменение клиента в новом/неотгруженном заказе - явная операция.

Жизненный цикл: новый → подтверждён → отправлен → завершён. Отмена до отправки освобождает резерв. После отправки доступен возврат с указанием поступления товара и возврата денег. Состояние оплаты вычисляется отдельно: не оплачен / частично / оплачен / возвращён. Выполнение: не отправлен / в пути / доставлен / возвращён. Оплата не обязана предшествовать отправке (возможна оплата при получении), но интерфейс явно предупреждает о долге. Редактирование состава после отгрузки блокируется.

## Основные сценарии

1. Менеджер открывает обзор → очередь → preview заказа → карточка → подтверждает → фиксирует платёж → отгружает → завершает. Клиент, склад, история и показатели меняются вместе.
2. Создание: клиент или новый контакт → товар и количество → доставка/скидка → проверка → сохранение → карточка с тем же ID. Ошибки сохраняют ввод.
3. Обращение: inbox → клиент → заказ → заметка/задача → черновик ответа по шаблону. Отправка остаётся симуляцией.
4. Склад: низкий остаток → товар → приход → движение → обновлённое доступное количество. Нельзя списать резерв.
5. Руководитель: период → канал или менеджер → отфильтрованные заказы → перераспределение → задачи.
6. Правило: редактировать → пробный запуск показывает кандидатов → включить/выполнить → журнал → созданная задача. Повтор не создаёт дубликат.

## Визуальная концепция: спокойное рабочее пространство

Сохраняем логотип, тёмный navy и характерный синий акцент. Из Attio/Linear берём компактность и ясность взаимосвязей. Палитра: sidebar #0B152B; ink #172238; muted #64748B; surface #FFFFFF; canvas #F5F7FB; border #E4E8F0; action #4263D5; action-soft #EDF2FF; success #087F67 / #E8F6F1; warning #9A6209 / #FFF4DF; danger #C13F4A / #FDEEF0. Цвет обозначает смысл; основной CTA один на контекст.

Inter: display 30/38 semi-bold, page 26/34 semi-bold, section 16/24 semi-bold, body 14/20 regular, metadata 12/16. Данные имеют табличные цифры. Сетка: базовый шаг 4 px; отступы 8/12/16/20/24/32; карточки radius 12, поля/кнопки 8, badge 6. Верхняя строка 64 px; body padding 28 px; таблицы 56 px (comfortable) или 44 px (compact). Тени только у плавающих поверхностей.

Обзор: приветствие и дата демо-снимка, четыре компактных KPI, широкий график оплаченных сумм, очередь внимания справа, затем недавние заказы и каналы. График показывает реальные точки демо-данных; никаких выдуманных процентов роста или прогноза без модели. Таблицы: читаемый заголовок, вторичная строка клиента, небольшие статусные chips, выделение выбранной строки, действия по контексту. Детальная карточка: статус/следующий шаг сверху, состав и история слева, клиент/доставка/сводка справа.

Компоненты v2: Button, IconButton, Input/Select/Textarea, Checkbox, Switch, Badge, Avatar, NavigationItem, Sidebar expanded/compact, Tabs, TableHeader/Row, KPI, Card, Modal, Drawer, Toast, EmptyState, Skeleton, Tooltip, SearchResult, TimelineEvent, Chart/Legend. Состояния default/hover/focus/disabled/error/selected создаются по применимости. Примитивы → semantic aliases → компоненты; WEB code syntax соответствует CSS custom properties. Исходная библиотека сохраняется как архив для сравнения.

Движение 160–220 мс на drawer, hover и смену состояния, с reduced-motion. Отдельные библиотеки анимаций не нужны для этих сценариев. Декоративный vortex или фоновые частицы не улучшают операционную работу.

## Доступность и адаптация

Проектируем по WCAG 2.2 AA: видимый фокус, имена icon-buttons, label/error-связи, статусы текстом, native dialog с возвратом фокуса, доступная таблица/альтернатива графику. Контраст проверяется численно. Полная сертификация AA не заявляется без ручных проверок и ассистивных технологий.

1440/1366: полный sidebar; 1024: compact; 768 и меньше: drawer и вертикальная композиция. Таблицы имеют собственную горизонтальную прокрутку, формы и детали не расширяют страницу. Минимум контролов 36–40 px для удобства, важные мобильные действия 44 px. Несохранённые изменения требуют явного выбора; ограничение localStorage объясняется без потери текущей сессии.
